## 一、卡片从哪来：不是配置生成，是预制体自带的

```
MonoWorldMapUIManager.SetupAllEntryButton()
  ├─ GetCurrentTabEntryList()                 // 取当前页签的列表
  └─ MonoWorldMapChallengePanel.SetupView(list, playFadeIn)
       ├─ 隐藏 emptyFlagList 全部 4 个
       ├─ 隐藏 allEntryList   全部 9 个
       └─ foreach (entry in list) { entry.SetActive(true); entry.SetupView(); }
```

列表的源头是 `AddEntryListForTab` @ `0x182D02CE0`：

```csharp
foreach (var entry in tabTrans.GetComponentsInChildren<MonoWorldMapEntryContainerBase>(true))
{
    if (!entry.enabled) continue;
    if (!entry.CheckEntryValid()) continue;    // ← 门禁
    _allEntryList.Add(entry);                  // +0xA8
    dataList.Add(entry);
}
```

**关键：卡片来自预制体子节点（`GetComponentsInChildren`），不是运行时按配置实例化的。**
所以每张卡的入口 ID 是**烘在预制体里的序列化字段**。

## 二、预制体里那张表

`MonoWorldMapEntryContainerBase` 的序列化字段（`+0x18`）：

```csharp
public int  entryID;        // +0x18
public int  index;          // +0x1C
public bool isFixedEntry;   // +0x20
```

`SetupContainerData` @ `0x182CFE4C0`：

```csharp
private void SetupContainerData() {
    var cfg = Singleton.someTable; cfg.Init();

    this.ContainerData = worldMap.HCIBJEOCENM(this.entryID, this.index);   // 查 WorldMap 表
```

## 三、门禁：三道

```
CheckEntryValid()                                  @ 0x182CFB4C0
  ├─ SetupContainerData()
  ├─ IsContainerDataValidIncludeRaidHint()         @ 0x182D00640
  │    ├─ if (ContainerData == null) return IsContainerDataValid();
  │    ├─ if (ContainerData.JONKHNOFPPH() == 8)    // FeatureType == 8 (记忆战场)
  │    │      额外按玩家等级做上下限判断
  │    └─ return IsContainerDataValid();
  └─ IsContainerDataValid()                        @ 0x182D00770
       └─ return ContainerData != null && ContainerData.NOIBCEBOLDE();
```

`OODENFBANCC.NOIBCEBOLDE()` @ `0x180A52510`：

```csharp
return this.WorldMapRow != null          // +0x18  FIGGCBHEGMC
    && this.ContentList != null          // +0x20  List<FNPIAMHMCKC>
    && this.ContentList.Count > 0;       // 必须非空
```

`ContainerData` 的构造（构造函数 @ `0x180A526F0` → `KEHFPGLKCDA()` @ `0x180A51F30`）：

```csharp
WorldMapRow = worldMapTable.GGMFAGLNJMM(entryID, index);       // 0x181076910
if (WorldMapRow == null) return;                               // ContentList 留空 → 无效
ContentList = worldMapTable.FAFJAGJDMOO(
                  WorldMapRow.NEOHNNNALBI(),   // ContentIDList
                  this.JONKHNOFPPH(),          // FeatureType
                  this.LFNDLLMAILF(),          // HJDECHBEEAP
                  true);                       // 0x181074DF0
```

`FAFJAGJDMOO` 对 `featureType == 1` / `== 2` 有特判分支，其余走 `ContentIDList` 通用路径；
`ContentIDList == null` 时会退到 `LLABBEIBJNH(...)` 拿兜底项（`0x18107565F`）。

## 五、补丁方案

### 主方案：改预制体（零风险）

`0x04EA20` 处 `entryID`：`1006` → `1012`

- `1006 = 0x03EE`，`1012 = 0x03F4`，**只差低字节一个字节**（`EE` → `F4`）
- LZ4 字面量级原地补丁，文件总长度不变（`.wmv` 文件名是 md5，长度不能变）
- 实测命中 bundle #848，payload 584,103 B，改在 block#2 压缩流内偏移 16389
- 复核：`entryID=1012`，文件长度 47,293,360 字节未变 ✓

### 风险与备用方案

迪拉克 `ContentIDList` 是空数组 → `NOIBCEBOLDE()` 会返回 false → 卡片可能被判无效而**直接消失**。

备用：`UserAssembly.dll` 偏移 `0xA5113B`（VA `0x180A5253B`）处
`7E 08`（`jle 0x180A52545`，即 Count<=0 时跳去返回 false）改成 `90 90`（nop），
使其落到 `B0 01`（`mov al,1`）。

副作用：其它「有行但内容为空」的入口（1001/1002/1007/1008）也会变成可见。
1000 / 1005 因 WorldMap 无行，`WorldMapRow == null` 仍然无效，不受影响。
