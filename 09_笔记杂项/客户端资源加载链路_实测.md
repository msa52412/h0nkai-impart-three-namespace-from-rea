# 崩坏3 v7.0 私服 —— 客户端资源加载链路实测

> 记录日期：2026-10-24
> 目的：解释「为什么改 `.wmv` 里的 prefab 完全不生效」，并给出后续可行路线。

---

## 一、起因

前一轮把 `0a95a351…wmv` 里 bundle #848 的 `MonoWorldMapEntryContainerBase.entryID`
从 1006（悬赏委托）改成 1012（迪拉克之海），字节级验证 100% 正确（两种独立 LZ4 解码器
都读出 `entryID=1012`），但游戏里第 6 张卡毫无变化。

随后尝试改 `UserAssembly.dll` 绕过逻辑判断，游戏直接报「文件缺失 UserAssembly.dll」。

---

## 二、DLL 为什么不能改（结论：这条路彻底封死）

`D:\BH3\7.0\BH3_Data\Native\UserAssembly.dll`（190,867,608 B）的 PE 结构：

```
PE32+ (0x20b), 11 sections
Certificate  RVA 0xb604050  size 0x2848     <-- Authenticode 数字签名
Export       RVA 0xb827000  size 0x200
Reloc        RVA 0xb828000  size 0x394480
```

**该 DLL 带 Authenticode 签名。** 改动任意 1 字节 → 签名链失效 → 启动器/反作弊
判定文件无效，对外报「文件缺失」。

实测证据：
- 改 2 字节后，文件大小、`MZ` 头、PE 签名、section 表全部完好，仅 2 字节差异；
- 但游戏仍报缺失 → 说明是**完整性/签名校验**，不是文件损坏。

已还原：`md5 = 2db62015ae66014f1533c39294ccd1d2`，`0xA5113B` 处字节 `7e 08`，
时间戳回到 2023/10/18。**此后不要再改这个 DLL。**

## 三、真正的资源加载链路（关键发现）

### 3.1 nginx 访问日志统计（一次完整游戏会话）

| 请求路径 | 次数 |
|---|---|
| `/asset_bundle/overseas01/1.1/...` | **18,020** |
| `.../editor_compressed/...` | **16,330** |
| `StreamingAsb/...` | 61（全部是 `BlockMeta_7_0.xmf`） |
| `*.wmv` | **5（全是 10/22 的 404）** |

**客户端从不通过 HTTP 取 `.wmv` 数据**，所有资源都从
`asset_bundle/overseas01/1.1/{data,event,ai}/editor_compressed/` 下载。

### 3.2 热更资源目录

```
D:\BH3\7.0\runtime\web\asset_bundle\overseas01\1.1\data\editor_compressed\
├── DataVersion.unity3d     134,274 B   清单（全加密，无可读串）
├── patch\patchconfig.xmf     7,836 B   补丁清单（**明文**）
└── data\                     822 个包
```

`data\` 下 822 个包，命名 `{uint32}_{SHA1}`，其中：

| 类型 | 数量 | 特征 |
|---|---|---|
| **明文 UnityFS** | **17** | 头部 `UnityFS\0`，仅 header 被 XOR 混淆 |
| **全加密** | **805** | 首 4 字节随机，整体加密 |

17 个明文包清单：

```
lua0 ×2  lua1 ×2  lua2 ×2  lua3 ×2  lua4 ×2   (Lua 字节码)
excel_output ×1  298,849 B   (本地化文本池)
setting ×2       ~1.9 MB     (设置)
bh ×2            ~938 B
sv ×2            ~900 B
```

> 注意：每个逻辑包都有**两份不同 SHA1 的副本**，客户端两份都会请求。

### 3.3 明文包的混淆规律（已部分破解）

17 个明文包的 header 前 0x30 字节**完全相同**，说明是**位置固定的 XOR 密钥流**，
与文件内容无关。用 908 / 938 / 298849 三个不同大小的文件做差分，已解出：

```
bundle 大小字段 = big-endian int64 @ 0x10
keystream[0x10..0x17] = 37 79 77 79 3B 9E 77 37
```

代入三个文件长度全部吻合（908 / 938 / 298849）。其余 header 字段（flags、
blocksInfo 尺寸）尚未完全解出。

SerializedFile 主体起点 = `0xAE`，头部为**大端**：
```
0xAE  metaSize   = 0x565   (1381)
0xB2  fileSize   = 0xC12BC (791,228)   <-- 与剩余 298,675 不符，含义待定
0xB6  version    = 17
0xBA  dataOffset = 0x1000
0xC2  unityVersion = "2017.4.18f1"
```

### 3.4 excel_output 不是入口数据表

`excel_output_048D75C0…`（298,849 B）内含 `OWEndless`、`Cover_` 等串，但
`FeatureType` / `EntryID` / `WorldMap` / `newbie37` **全部 0 命中**；
上下文全是中文 UI 文案（「修改队伍名称」「还不够呢，补充」「前往输入码？」…）。

→ **它是本地化字符串池，不是 WorldMapEntry 数据表。**
入口的 `FeatureType` 在剩下 805 个全加密包里。

### 3.5 Lua 是编译字节码，不是源码

`lua1` 里 `WorldMapUIManager` 字符串 **0 命中**（10 个 lua 包全部 0 命中），
但 `Task_6`、`MapPanel0`、`Challenge`、`Endless` 有命中，且呈
`ap* dainer/ UI _V2 2D Tab/Challen 3D Task_6/C` 这种**碎片化**分布
→ Lua 5.x / LuaJIT **字节码**，字符串常量被长度前缀和 opcode 隔开。
不能直接改源码，只能改等长字节。

## 五、prefab 补丁「不生效」的两种可能

### 可能 A：客户端根本不读这个 wmv

日志显示 824 个 bundle 全部走 `editor_compressed`，`.wmv` 数据 0 次 HTTP 请求。
但客户端确实请求了 `BlockMeta_7_0.xmf`（块索引），说明它可能**本地读取** wmv。
两种解读都成立，需要用实验区分。

### 可能 B（更可能）：补丁生效了，但 1012 本身是「打不开的入口」

`EntryID 1012`（迪拉克之海）在服务端配置里是**残缺**的：

```
FeatureType      [108]
ContentIDList    []          <-- 空！没有任何可玩内容
UnlockLevel      25
VersionTagMinLv  30
```

迪拉克之海是**已关闭玩法**，入口即使被正确指向，点进去也是空/无反应
—— 这与「点击也没变化」的表现完全一致。

**这是之前误判的关键点：把「指向一个打不开的玩法」当成了「补丁没生效」。**

## 六、决定性验证实验（已安装）

把 Task_6 槽位的 `entryID` 从 **1006 改成 1005**。

`1005` 是 prefab 里有槽位、但 `WorldMap.json` 里**完全不存在**的 EntryID
（服务端 EntryID 集合：1001..1004, 1006..1013, 2001..2004, 2007, 9999）。

| 观察结果 | 结论 |
|---|---|
| 第 6 张卡**变空白/消失** | prefab 补丁**生效**，wmv 是正确来源 → 下一步解决「让 1012 变可玩」 |
| 第 6 张卡**仍是悬赏委托** | prefab 补丁**未被加载** → 必须攻破 805 个加密包 |

工具：`D:\Carol-start\_rea\patch_wmv.py`

```bash
python patch_wmv.py status      # 查看当前 entryID
python patch_wmv.py set 1005    # 装验证补丁
python patch_wmv.py set 1006    # 完全还原成原版
python patch_wmv.py restore     # 从备份整文件还原
```

技术要点：`entryID` 的低 2 字节在 LZ4 **字面量**区（可原地改），
高 2 字节恒为 0 且落在 **match** 区（改不了）—— 但 entryID < 65536，
所以只改低 2 字节即可任意设值。

## 七、服务端侧已确认的事实

- `GetWorldMapDataReqHandler` 返回的是**硬编码 blob**（只含世界地图开启状态
  WorldMapId/BeginTime/EndTime），**不含**入口卡片的 `FeatureType` 等展示数据。
  客户端卡片的 `FeatureType` 来自客户端 excel，服务端改不了。
- 历史教训（代码注释留档）：改这个 blob 里任何一个时间字段都会导致
  世界地图渲染失败、全部入口消失。**不要碰。**
- `PlayerLoginReqHandler` 已加 `SwitchDataNotify` 推送
  `EndlessSwitchData{EndlessType=2(Openworld), PlayerGroup=1}`，
  用于点亮迪拉克之海的**功能开关**。

## 八、后续路线

### 若实验证明 wmv 生效
1. 让 `1012` 变可玩：补 `ContentIDList`、`UnlockLevel=1`、`forceShowContent=1`
   —— 但这些在客户端 excel 里，需要能改 excel 包。
2. 或者：把 Task_6 指向一个**服务端已配置完整**的入口，验证点击链路，
   再逐步替换成迪拉克。

### 若实验证明 wmv 不生效
必须攻破 805 个全加密包。可行切入点（按性价比排序）：
1. **反汇编 `UserAssembly.dll`** 找解密函数 —— 手头已有符号表（310,575 条）
   和带符号解析的反汇编器 `fn.py`。搜 `UnityFS` 魔数比较、`LZ4_decompress` 调用点、
   `BlockMeta` 字符串引用。
2. `BlockMeta_7_0.xmf`（14,121 B，加密）—— 疑似含每块 hash，改包后校验会失败。
3. `patchconfig.xmf`（明文，60 条补丁包清单）—— 服务端可控制下发，
   但需要能产出合法包。
