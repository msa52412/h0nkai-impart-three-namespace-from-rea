### 3. 字段布局与结构

`MonoWorldMapEntryContainerBase` 序列化布局（对象起始 + 偏移）：

```
+0x00  m_GameObject  (fileID 4 + pathID 8 = 12)
+0x0C  m_Enabled     (1) + pad 3
+0x10  m_Script      (12)  pathID = 0x71f1c4363e4ac8df（12 个实例全部相同）
+0x1C  m_Name        (4) = 0（空串）
+0x20  entryID       (4)   ← 补丁改这里
+0x24  index         (4)   全部为 0
+0x28  isFixedEntry  (1)
```

源码字段声明顺序（`MoleMole.cs:970608`）：`entryID`(+0x18) → `index`(+0x1C) → `isFixedEntry`(+0x20)。
运行时对象头 0x18，故序列化 +0x20 ↔ 运行时 +0x18，偏移差 8 成立。

12 个实例的 `m_Script` pathID 完全相同，且类里有 `entryImage`/`TitleText`/`containerGO`/`missionBtn`
等 UI 引用 —— **确认是卡片组件，不是别的东西**。

### 6. 发现的强线索：Lua 硬编码了节点路径

`lua1_EB7A6457...` 里有完整路径字符串：

```
.../WorldMapUIManager_V2/Canvas2D/Pages/TypeTab/Challenge
.../3D/MapPanel0/Task_6/Cover
```

`lua1_E7D1D9F0...` 里同样有 `...Tab/Challenge` + `...3D/MapPanel0/Task_6/Cover`。

**含义**：Lua 层直接按名字操作 `Task_6` 节点。这也解释了为什么「把 Task_6 改名做诊断标记」
不可行 —— 已立即还原（Lua 里 `Task_6` 各出现 2 次，改名会让 Lua 找不到节点）。

**但 Lua 里没有 `entryID` 字段名字符串**，所以它大概率不改 entryID，只做点击绑定/显隐。

### DLL 补丁的作用与副作用

`OODENFBANCC.NOIBCEBOLDE()`：
```csharp
return WorldMapRow != null && ContentList != null && ContentList.Count > 0;
```
迪拉克 1012 的 `ContentIDList` 是 `[]`，原本会被判无效 → 卡片隐藏。
`90 90` 后，「有 WorldMap 行、ContentList 非 null 但 Count=0」也返回 true。

**副作用**：1001/1002/1007/1008/1011 这几个同样「有行但内容空」的入口也会变可见。
**安全性**：`DoSetupView` 对 `count=0` 走默认分支（`lea edx,[rax-1]` → -1，不匹配 0/1/2），
不会空引用崩溃。
