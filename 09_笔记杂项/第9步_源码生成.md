## 2. 生成原理

三份数据各管一段，互不重叠：

```
global-metadata.dat（已解密）
  ├─ bh3_types_v5.txt       → namespace / 类型名 / token / 父类 / 方法区间
  ├─ bh3_fields.tsv         → 字段声明顺序 + 字段类型
  ├─ bh3_methods_v2.tsv     → 方法名 / 返回类型 / 参数名 + 参数类型 / flags
  ├─ bh3_generic_params.tsv → 泛型形参真实名（T / TKey / TSource …）
  ├─ bh3_properties_v2.tsv  → 属性（含 getter/setter 有无）
  └─ bh3_events.tsv         → 事件
字段布局（bh3_layout4.tsv / bh3_structs2.tsv）
  └─ 每个字段的 +0xNN 偏移、字节数、类型总尺寸、置信度
Ghidra（已贴符号 + 结构体 + 签名 + noreturn）
  └─ 每个方法的反编译体（按 RVA 索引）
```

生成器做的事：

1. **类型种类**由父类推断 —— `System.Enum`→`enum`、`System.ValueType`→`struct`、
   `System.MulticastDelegate`→`delegate`、**全部方法抽象**→`interface`、其余→`class`。
2. **字段偏移**直接标在注释里（`// +0x28  (8 字节)`），并按布局算出类型总尺寸。
3. **泛型**用 `bh3_generic_params.tsv` 里的真实形参名还原：
   `List\`1` + 形参 `T` → `List<T>`；字段类型 `!0` → `T`。
4. **显式接口实现**（方法名里带点，如 `System.IDisposable.Dispose`）保留点号、
   去掉 `global::` 前缀、不加访问修饰符 —— 这本身就是合法 C#。
5. **方法体**按 RVA 从 `bodies.tsv` 取；同一地址被多个方法共用时，
   额外标一行 `// 共享体：N 个 C# 方法共用此地址，Ghidra 代表函数 X`。

## 4. 已知局限

| 局限 | 原因 | 影响 |
|---|---|---|
| **嵌套类型不归属父类** | 元数据的 `nestedTypes` 数组还没解出，只有 `nestedCount` 计数 | 10,390 个嵌套类型与顶层类型平铺在同一命名空间里，名字原样保留 |
| **static 字段被算进实例布局** | 字段记录里没有 static 位（§9L.3），纯打包算法不区分 | 有真实 static 字段的类（单例、缓存）实例偏移会偏；`P!` 类型 6,812 个需注意 |
| **泛型共享体显示代表类型** | 同一段原生代码服务多个 C# 类型，反编译只能取一个 | 注释里已标「共享体：N 个方法共用」+ Ghidra 代表函数名 |
| **枚举没有数值** | 元数据里的常量表未解 | 只有成员名与顺序，没有 `= 3` |
| **没有 attribute / 方法常量** | 未解 | 类/方法上没有 `[Serializable]` 之类的标注 |
| **函数体覆盖率随导出进度增长** | 反编译 31 万个函数需要数小时 | 见下节 |
| **`probe_*` 残留名** | 早期探针脚本的命名 | 只出现在 Ghidra 函数名注释里，不影响结构 |

## 6. 复现

```bash
# 1) 生成声明骨架（不需要 Ghidra，6 秒）
python gen_cs.py --out src

# 2) 导出反编译体（远端，可续跑）
scp DumpBodies.java nas@192.168.0.104:~/re/ghidra/scripts/
scp body_list.txt    nas@192.168.0.104:~/re/sym/
GHIDRA_HEADLESS_MAXMEM=3G ~/opt/ghidra_12.1.4_PUBLIC/support/analyzeHeadless \
  ~/re/ghidra/proj4 bh3fix -process UserAssembly_fixed.dll -noanalysis \
  -scriptPath ~/re/ghidra/scripts \
  -postScript DumpBodies.java ~/re/sym/body_list.txt ~/re/sym/bodies.tsv

# 3) 合并
python gen_cs.py --out src --bodies bodies.tsv

# 4) 浏览
python serve_src.py --port 8765      # → http://127.0.0.1:8765/
```

`body_list.txt` 的排序不是随机：先按命名空间优先级
（`proto` → `MoleMole` → `IFix` → `UnityEngine` → `System` → …），
再按「共用该地址的方法数」降序，所以即使只跑了一小部分，覆盖率也已经不低。
