# 世界地图卡片槽位机制 —— isFixedEntry 才是关键

> 2026-10-24 18:00
> 这篇解决了「为什么改了 prefab 的 entryID 完全没反应」这个卡了好几轮的问题。

---

## 一、结论先行

`MonoWorldMapEntryContainerBase` 里有三个序列化字段：

| 偏移（对象起始） | 字段 | 说明 |
|---|---|---|
| +0x20 | `entryID` | 卡片绑定的 WorldMap EntryID |
| +0x24 | `index` | 槽位序号 |
| **+0x28** | **`isFixedEntry`** | **1 = 固定槽位，0 = 动态槽位** |

**`isFixedEntry = 0` 时，序列化的 `entryID` 在运行时被完全忽略**，
卡片内容由活动列表动态填充。

### 预制体里 12 个槽位实测

```
1010 @0x01CB70  isFixed=1        1000 @0x021DB4  isFixed=0  ← 动态
1005 @0x02FDB0  isFixed=0 ← 动态  1002 @0x02FFF8  isFixed=1
1004 @0x040818  isFixed=1        1001 @0x044670  isFixed=1
1005 @0x04EA20  isFixed=0 ← 动态  1007 @0x04F530  isFixed=1
1008 @0x0527D0  isFixed=1        1003 @0x057178  isFixed=1
1013 @0x059F70  isFixed=1        1009 @0x0605E8  isFixed=1
```

**`0x04EA20` 就是之前一直改的那个槽位 —— 它是动态槽。**

所以：
- 把 0x04EA20 的 entryID 从 1006 改成 1012（迪拉克）→ 无效
- 改成 1005（不存在的 EntryID）→ 依然无效
- 两次实验都「毫无变化」，原因就在这里，**不是补丁没生效，是字段根本没被读**

## 二、为什么之前的排除清单全部指向错误方向

之前列了 8 条排除项（第二份 wmv、Junction 副本、HTTP 下载、Unity Caching、
IFix 热补丁、Lua 改 entryID、AddEntryListForTab 写入、BlockMeta CRC），
全部围绕「客户端有没有读到这个文件」打转。

实际上客户端**一直读得到**，只是读到的 `entryID` 字段没人用。

补充两个本轮确认的事实：

1. **440 个 wmv / 16.13 GB 全量裸字节扫描**：只有 `0a95a3510bffb1a31fdef2cae36e8783.wmv`
   含 `Task_3/Task_4/Task_6/Task_9` 卡片节点字符串 → **改的文件一直是对的**。
   （其他 wmv 里有 `MapPanel`/`Canvas2D`/`TypeTab`/`OWEndless`，是世界地图 UI 的其他部分）
2. **`AssetNativePlugin.dll` 的导出表**全是 wmv 块文件系统 API
   （`CheckValidtionByBlockFileInfo`、`GetBlockFileInfoMD51/52`、`IsBlockFileInfoChange`），
   而且 `IsBlockFileInfoChange` 比较的是 **FileName_MD5**（文件名里的 MD5），
   不是内容哈希 → 本地 wmv 内容改动**不会**被拒绝。

## 三、LZ4 字面量约束（为什么不能把 isFixed 从 0 改成 1）

`wmvkit.patch_same_length` 只能改 LZ4 **字面量**区的字节。

- `entryID` 的低 1~2 字节通常是字面量 → 可以改
  （1000~1013 的高字节都是 `0x03`，只有低字节不同，所以改 1 字节就够）
- `entryID` 的高 2 字节（恒为 `0x00`）落在 match 区 → 改不了
- **`isFixedEntry` 那个 `0x00` 也落在 match 区 → 无法从 0 改成 1**

所以「把动态槽转成固定槽」这条路走不通，只能**挑本来 `isFixed=1` 的槽位**。

> 试过整块重压缩（LZ4 HC）：block#2 原 31381 B，HC12 压到 31228 B，
> 补零到原长度后 `bundle_payload` 返回 None（严格解码器不接受尾部填充）。
> 必须精确等长，所以整块重压缩方案暂时不可用。

## 2026-10-24 补充：为什么卡片会「消失」，以及为什么迪拉克入口做不出来

### 1. 卡片消失是机制的必然结果，不是补丁失败

```
CheckEntryValid(0x182CFB4C0)
  SetupContainerData()
  if (IsContainerDataValidIncludeRaidHint())
       AddRealEntry();  return true;      // 卡片显示
  else
       SetEntryVisible(false);            // 卡片隐藏
       SetupEntryNoneFlag();
       return false;

IsContainerDataValid(0x182D00770)  =>  _ContainerData != null && NOIBCEBOLDE()
NOIBCEBOLDE(0x180A52510)           =>  excel行!=null && List!=null && List.Count>0
```

`List<FNPIAMHMCKC>` 由 `FAFJAGJDMOO(contentList, featureType, ...)` 生成，
而 `contentList` 来自 excel 字段 `ContentIDList`。
**1012 和 1007 的 ContentIDList 都是空的 → 列表 Count=0 → 卡片被隐藏。**

### 2. 迪拉克之海（1007）在 excel 里本来就是「关闭」状态

`WorldMap.json`（服务端副本，228 行）：

| EntryID | FeatureType | ContentIDList | forceShowContent |
|---|---|---|---|
| 1007 迪拉克之海 | [3] ENDLESS | **[]** | **2 = ForceToHide** |
| 1012 量子奇点 | [108] QUANTUM_ENDLESS | **[]** | 0 = Normal |

- `enum WorldMapShowContentListType { Normal=0, ForceToShow=1, ForceToHide=2 }`（`MoleMole.cs:970594`）
  就是 `forceShowContent` 的取值域，1007 被显式标记为「强制隐藏」。
- **全表 228 行中，没有任何一行同时满足 `FeatureType==3` 且 `ContentIDList` 非空。**
  也就是说：迪拉克卡片连「原本该显示」的配置都不存在——这正是「已关闭玩法」的实现方式。

### 3. 客户端 excel 表无法直接改

全量搜索 `ContentIDList` / `forceShowContent` 字符串的结果：

| 搜索范围 | 体量 | 命中 |
|---|---|---|
| `Data/data/*.unity3d`（421 个） | 0.52 GB | 0 |
| `StreamingAssets/Asb/pc/*.wmv`（440 个） | 16.13 GB | 0 |
| `BH3_Data`（resources.assets 等） | ~58 MB | 0 |

客户端 excel 是**二进制 ExcelMeta 格式**（不含字段名字符串），所在 bundle 被加密。
17 个明文包里的 `excel_output` 其实是**本地化字符串表**（TextMap），不是配置表。

### 4. 其他路线也堵死

- **DLL 补丁**：`BH3_Data/Managed` 下没有任何 DLL，逻辑全在 `Native/UserAssembly.dll`
  （190 MB，带 Authenticode 签名），改一个字节即失效。
- **IFix 热补丁**：运行时 `IFix.Core` 确实存在，但 `IFixPatch` / `.dll.patch` / `VirtualMachine`
  字符串零命中（ASCII 与 UTF-16 都搜过），发布版大概率裁掉了补丁加载入口。
- **服务端**：`GetWorldMapDataRsp` 是硬编码 blob（仅 WorldMapId/BeginTime/EndTime），
  不含 FeatureType / ContentIDList，excel 根本不下发。

### 5. 可行的替代做法

选一个 **ContentIDList 非空** 的 EntryID 填入固定槽位，卡片就能正常显示并可点击：

| EntryID | FeatureType | 内容条数 | 解锁等级 |
|---|---|---|---|
| 1003 | 2 EXTRA_STORY | 1 | 24 |
| 1006 | 114 NEWBIE（悬赏委托） | 7 | 15 |
| 1009 | 9 | 31 | 15 |
| 1004 | 8 RAID | 32 | 35 |
| 2003 | 100 | 15 | 50 |

```bash
python patch_slot.py set 0x059F70 1006     # 悬赏委托
python patch_slot.py set 0x059F70 1003     # 编年史
python patch_slot.py restore               # 全部还原
```

**局限**：这样只改「显示哪个入口」，无法改变入口指向的玩法——
因为玩法类型（FeatureType）和内容列表（ContentIDList）都锁在客户端 excel 里。
要真正做出「指向迪拉克之海的新入口」，必须攻克第 3 节的二进制 excel 表。

### 6. 附：明文包解码格式（本轮破解，可复用）

```
[UnityFS\0][54 字节头部，0x08 起为 XOR 流]
[blocksInfo：LZ4 压缩]
[块数据：每块 "mr0k"(4B) + 16B 哈希 + LZ4 块]
```
LZ4 块需要 64 KB 零字典前缀：`lz4_decode(blk[20:], bytes(65536))`，取输出 `[65536:]`。
变体：部分包（如 `lua1_*`）54 字节头部后直接是 `mr0k` 块，blocksInfo 在文件末尾，
`wmvkit.try_bundle` 会失败，需从尾部解析。
